# Logging On for the First Time & Setting Up Two-Factor Authentication (2FA)

This article outlines the process of logging into a high-performance computing (HPC) cluster for the first time at George Washington University, including how to establish two-factor authentication (2FA) required for all subsequent logins. We suggest reading through this tutorial in full prior to accessing your account for the first time.

**Note:** Research Technology Services (RTS) uses a separate set of 2FA authentication from GW’s other IT services (Gmail, GWeb, etc.), thus 2FA codes from those sources cannot be used for signing in to Pegasus, Cerberus or any other HPC cluster ran by RTS. Additionally, you must set up 2FA for each individual cluster you wish to access. For instance, if you have an account on Pegasus and an account on Cerberus, you should repeat this process twice: once on Pegasus, and once more on Cerberus, resulting in two distinct 2FA code generators.

## Background Information on 2FA

Two-factor authentication, or 2FA, is a cybersecurity measure used to improve the security of signing in to any given online service. Rather than the standard check for a single, known piece of information (usually a password of some kind), 2FA requires on top of that a separate code that the user would have access to. Most commonly, this is a regularly-updating code generated by a device they own, with possession of said device constituting the second factor (knowledge of the password being the first). By double-checking a user passes both checks, the likelihood of a bad actor breaching the system and gaining access to your account is greatly reduced, especially in the event one of the factors is compromised in some manner.

In the context of HPC clusters at GW, the first factor is the passphrase locking your SSH key pair, with the second factor being the authenticator code generated on your mobile device. Note that the first factor is something you know, and the second factor is something you have—2FA is most effective when involving multiple ways of confirmation in this manner. Had we replaced the regularly changing generated codes with a second, unchanging password, it would be susceptible to the same attacks and flaws as the first password, comprising security.

## Process for Establishing 2FA on HPC

Before we begin on the proper setup, a few things will need to be confirmed and installed on the part of the user. First, you will need an account on the particular cluster you wish to access; if you haven’t already, make sure to submit a request for access via the [HPC Access Request form](https://hpc.gwu.edu/getting-access/), and tick the boxes for the cluster(s) you wish to use. Second, you will need to have an authenticator app of some kind on your mobile device; GW’s recommendation is [Microsoft Authenticator](https://www.microsoft.com/en-us/security/mobile-authenticator-app), but this process will work with other software such as Google Authenticator or Authy.

**Note:** During the account creation process, you should have received an email from hpchelp@gwu.edu with the subject “HPC \[Cluster Name\] 2FA”. The body of the email should contain a one-time use code for when initially signing in. Please make sure you complete these steps during your first session, otherwise you will be unable to access the cluster again until obtaining another one-time use code\!

1. Log in to the cluster you want to set up 2FA for. This can be done by inputting “ssh \[UserID\]@\[clustername\].arc.gwu.edu” in your Terminal/Command Line, then pressing **Enter**.  
   1. You will then be prompted for the passphrase you locked your SSH key pair with. If you are uncertain what this means, please check the article [How to: Generate SSH Keys](https://ithelp.gwu.edu/en-us/article/1533433). Input your passphrase, then press **Enter**.  
   2. Afterwards, you will be prompted to enter a Verification Code—this is where your 2FA code will be submitted once your authentication is properly set up, but for now, please input the emailed one-time code for access, then press **Enter**.  
      1. **Note:** In the majority of command line interfaces (CLIs) such as Terminal in Mac OS and GitBash in Windows, the computer will recognize but not display your inputs for these two substeps. This is done as a security precaution to avoid malicious programs like screenreaders to steal your personal information by looking at what is typed. Do not be concerned if you see nothing appear as you type; simply press **Enter** once finished, and try again if it fails.  
2. Once within the cluster, input “google-authenticator” and press **Enter**.  
   1. You will then be asked a question. For this and all future questions in this program, please input “y” and hit **Enter**.  
   2. A QR code should appear within the program. Scan this code within your mobile app to add the generator to your phone.  
      1. **Note:** We recommend putting the Terminal/Command Line in fullscreen, as the QR Code is known to not show in full in smaller windows.  
   3. Below the QR Code are what are known as your “emergency codes”—these are one-use only codes that can be used in place of your standard generator in the instances you don’t have access to your device. Take a screenshot or otherwise save these in a safe place on your device.  
      1. **Note:** Please use these emergency codes sparingly; you will only ever get those five and will need an administrator to reset them should you use them all\!  
   4. The program will then prompt you to enter the six-digit code obtained from scanning the QR code; type this code in, then hit **Enter** to proceed.  
   5. Afterwards, you will then be asked a series of questions. Make sure to answer all of them with “y” and hit **Enter** to proceed.  
3. Prior to logging off, open a new instance of Terminal/Command Line and reattempt Step 1 with your mobile code instead in Step 1(b).  
   1. If successful, you have set up 2FA on that specific HPC cluster\! Feel free to log off of both instances.  
   2. Otherwise, return to your original instance of Terminal/Command Line and reattempt Step 2\.  
4. If you wish to set up 2FA for multiple clusters, repeat Steps 1-3 for a different cluster. For simplicity of organization, we suggest renaming the generators that appear in your authenticator app to that of the cluster it is associated with. This avoids confusion due to the default names often being similar across various HPC clusters.
